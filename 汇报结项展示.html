设计理念Key Decisions

Key Decisions

三个关键设计决策

01

正式前端工程

不继续堆静态 HTML，而是使用 Vue 3 + Vite 支撑路由、组件、状态和构建部署。

02

模块化单体

课程周期内优先保证交付效率，同时按业务域划分 Controller 和 Service。

03

有来源问答

知识库问答坚持 sources 返回和低置信度提示，无可靠依据时不编造政策。

前端隐藏不是安全措施，后端必须校验权限、数据范围和对象归属。

RBAC + Data Scope + State Machine
Engineering choices under course constraints

Principle

可信

优先基于知识条目、标准答案和附件证据回答。没有可靠来源时，返回低置信度提示或“未检索到可靠依据”。

Codex-first · Responses API fallback · Keyword fallback

工具使用与问题Tools & Issues

Tools & Lessons

大模型加速开发，但关键规则必须人工确认

大模型使用场景

  • 需求提取、用户故事、接口草案和文档表格。
  • Vue 页面、DTO、Service、测试骨架生成。
  • SQL、构建、权限范围问题调试分析。
  • README、部署说明、结项汇报材料整理。

遇到的问题

  • 前后端 mock 与真实接口字段需要持续对齐。
  • H2 与 Kingbase/PostgreSQL 需要保持兼容意识。
  • RAG 依赖外部模型和向量库，必须有降级。
  • 依赖安全、E2E、小程序联调仍是后续增强项。
经验：先文档后实现，先闭环后扩展；前端隐藏不等于安全，后端权限和状态机才是主防线。
